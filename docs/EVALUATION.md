### 工程与检索回归

63 项 pytest 覆盖原有行为及索引幂等、commit 隔离、旧数据读取、分块行号、中文检索、目录分页、证据取回、核验逐项覆盖、补证停止、批次恢复和费用预留。Ruff 检查通过。

固定检索集包含 6 条有预期文件的查询与 2 条预期零命中的查询。6 条查询的 Recall@5 均为 1.0，零命中检查通过。语料与问题规模固定，记录中保留返回字节数和检索耗时。该结果对应合成检索语料，见 [检索评测](../examples/v0.2/evidence-live.json)。

Pro 对 6 条合成证据的实测判定均与预设标签一致，覆盖无关引用、文档声明被写成实测、版本冲突、过期维护记录、无依据性能结论和正确版本陈述。离线模式使用预置标签做协议回放，真实模型模式标记为 live_model_synthetic_evidence。

### 受控错误与恢复

[补证案例](../examples/v0.2/repair-demo/report.md) 使用真实 GitHub 数据和真实 Flash/Pro，并明确向初始草稿注入“Java 构建目标为 8、仅引用 README”的错误。Pro 退回缺少依据的条目，Flash 全文检索后引用父 POM，将构建目标修正为 Java 17，通过第二轮核验。该任务使用 8 次模型调用、7 次 GitHub 请求、1 次全文检索，耗时 31.471 秒，费用估算 0.339831 元。初始草稿、问题反馈和最终核验都随案例保存。

该案例中 Pro 还要求摘要说明构建目标，体现审查反馈可能同时涉及事实依据与表达完整性。模型核验理由仍需结合原文和条目目的复核。

一次 Pro 请求中断后未返回 usage，任务暂停并保留 0.540540 元最高预留。操作者明确接受该费用上界后，同一任务通过 resume 恢复核验，记录保存在 [恢复案例](../examples/v0.2/recovery/report.md)。该调用的实际用量仍未确认，预留费用持续计入累计上限。

全部开发验收累计已确认用量的保守费用为 13.386183 元，另有 0.540540 元未知用量预留，总计费上界 13.926723 元，低于原 20 元预算。新发生的未知用量会继续冻结调用。账本快照见 [费用汇总](../examples/v0.2/cost-summary.json)。费率快照为 2026-11-12，2026-11-13 复核相同。 [官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

### 结果含义

review.status=passed 表示独立 Pro 调用通过了所给片段的辅助审查。source_coverage 表示确定性条目有引用 ID。事实语义正确性与实际运行效果应结合原文和独立验证解读，人工整体评分仍保持未评分状态。统计在导出时从持久化账本重算，token 合计只包含已返回 usage 的调用。

## v0.1.0 历史记录

测试日期为 2026-11-12，模型为 deepseek-flash，运行 SDK 为 deepagents 0.7.35。

## 验证方式

- pytest 覆盖 38 项离线回归，外部 HTTP 全部由 MockTransport 提供。
- smoke 包含技术栈、维护、部署、比较及证据不足 5 条问题。
- 合成回放运行真实 Deep Agents 图和工具边界，脚本模型的预期输出仅用于流程回归。
- live 使用真实 GitHub 与 DeepSeek，单次回答对照使用相同模型和原始问题，无 GitHub 工具。

## 首轮真实运行

单条调研任务 3a311fb31de6 完成端到端输出，使用 16 次模型调用、11 次 GitHub 请求，累计输入 217581 tokens、输出 6555 tokens，耗时 42.721 秒，保守费用估算 0.487602 元。

首次 5 条问题集完成 2 条，其余 3 条在资料积累后触发上下文上限。原始数据保留在 examples/evaluation-initial.json。

检查发现初始提示词可能增加用户未要求的硬性条件，且压缩阈值与应用的上下文上限不匹配。随后两轮完成数分别为 1/5 与 3/5，发现了摘要反复复制资料、目录证据校验过严、报告引用字段易被省略等问题。调试记录保留在 examples/evaluation-intermediate.json 与 examples/evaluation-before-compact-summary.json。

修复包括明确条件提取约束、原始需求与证据索引补回、简短摘要、必填引用字段和预算收敛提示。评测中 Spring AI Alibaba 的仓库地址更正为 alibaba/spring-ai-alibaba，每题按指定目标分析一至两个仓库。各轮存在配置与地址调整，数据用于复现调试轨迹。

## 指标说明

source_coverage 统计确定性 claim 与条件判定是否填写证据 ID。程序还校验 ID、仓库与 commit。事实正确性和条件正确性需要逐项人工评分，原始结果中的 null 表示尚未评分。

对照模型仅收到原始问题，Agent 额外拥有领域提示词、当前日期、规划与 GitHub 工具。信息访问条件存在差异，本次记录展示工程行为与失败类型。费用以官方高峰价格保守估算，服务商实际账单可能受时段和缓存影响。
